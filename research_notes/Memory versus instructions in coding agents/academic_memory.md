# Academic and empirical evidence on memory mechanisms in LLM agents, with attention to coding agents

*Method note: WebSearch was unavailable during this research (HTTP 402/429 on every attempt). All findings below therefore come from primary sources fetched directly from arXiv (abstract pages and, where noted, full HTML of the paper). Venues are reported only when they appeared in the arXiv metadata; otherwise the citation is by arXiv ID and year. Several of the most coding-specific papers are August–November 2026 preprints for which only the abstract was verified — these are explicitly marked as such and should be treated as stronger than marketing but weaker than peer-reviewed work.*

## Key Question 1: What do the canonical memory-focused papers and benchmarks actually show about performance gains?

### Takeaway
Memory mechanisms produce large, reproducible gains on narrowly defined retrieval/consistency tasks (MemGPT: +28 to +58 accuracy points on deep memory retrieval), but the headline numbers come from synthetic or conversational QA benchmarks, not from real software work. On realistic long-horizon chat benchmarks the same mechanisms still leave large gaps: commercial memory assistants score 0.25–0.71 where offline reading of the whole history scores 0.92, and long-context LLMs lose 30–60% of their accuracy when the evidence is scattered in a long history. Structured/agentic organization (graphs, multi-key indexing, time awareness) reliably adds single-digit to low-double-digit gains over plain vector RAG, at a cost in tokens and complexity.

### Cited Findings
- **MemGPT (Packer et al., 2023/2024, arXiv:2310.08560; paper metadata lists ICML)** — Deep Memory Retrieval accuracy on the Multi-Session Chat dataset: GPT-3.5 Turbo 38.7% → 66.9% with MemGPT; GPT-4 32.1% → 92.5%; GPT-4 Turbo 35.3% → 93.4%. ROUGE-L recall improved from 0.394→0.629, 0.296→0.814 and 0.359→0.827 respectively. The baselines saw a *lossy recursive summary* of the prior five sessions; MemGPT had the full history but had to page it in via function calls. — [Source](https://arxiv.org/abs/2310.08560) / [full text](https://arxiv.org/html/2310.08560v2)
- **MemGPT, nested key-value retrieval** — GPT-3.5 drops to 0% accuracy at one nesting level; GPT-4 and GPT-4 Turbo hit 0% by three nesting levels; MemGPT with GPT-4 is unaffected by nesting depth up to four levels. MemGPT with GPT-4 Turbo or GPT-3.5 begins to degrade at two levels. — [Source](https://arxiv.org/html/2310.08560v2)
- **MemGPT, document QA** — fixed-context baselines are capped by the retriever and degrade when documents must be truncated to fit; MemGPT's accuracy is roughly flat as the number of retrieved documents grows because it can issue multiple paginated retrieval calls. Authors note MemGPT "will often stop paging through retriever results before exhausting the retriever database" — a real, documented failure mode. — [Source](https://arxiv.org/html/2310.08560v2)
- **Generative Agents (Park et al., 2023, arXiv:2304.03442)** — natural-language memory stream + periodic synthesis into higher-level "reflections" + relevance/recency/importance retrieval. The evaluation is *qualitative* (believability of emergent social behavior in a 25-agent sandbox, e.g. a party rumor spreading over two days); an ablation shows observation, planning and reflection each contribute to believability. No task-accuracy benchmark is reported. — [Source](https://arxiv.org/abs/2304.03442)
- **LongMemEval (Wu et al., 2024; ICLR 2025; arXiv:2410.10813)** — 500 human-curated questions, five abilities (information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention); LongMemEval-S ≈115k tokens/question, LongMemEval-M = 500 sessions ≈1.5M tokens. On a *simpler* 97-question subset with only 3–6 sessions: offline reading with GPT-4o = 0.9184 accuracy; ChatGPT with GPT-4o = 0.5773 (37% drop), ChatGPT with GPT-4o-mini = 0.7113; Coze with GPT-4o = 0.3299 (64% drop), Coze with GPT-3.5-turbo = 0.2474. — [Source](https://arxiv.org/html/2410.10813v2)
- **LongMemEval, long-context LLMs** — oracle (evidence sessions only) vs full 115k-token history: GPT-4o 0.870 → 0.606 (30.3% drop); Llama 3.1 70B 0.744 → 0.334 (55.1%); Llama 3.1 8B 0.710 → 0.454 (36.1%); Phi-3 14B 0.702 → 0.380 (45.9%); Phi-3.5 Mini 4B 0.660 → 0.342 (48.1%). — [Source](https://arxiv.org/html/2410.10813v2)
- **LongMemEval, which memory designs help** — decomposing sessions into *rounds* beats storing whole sessions; further compression to extracted facts hurts overall QA but helps multi-session reasoning; adding extracted facts to the index keys gives +9.4% recall@k and +5.4% QA accuracy; time-aware query expansion gives +6.8–11.3% recall on temporal questions; Chain-of-Note plus structured (JSON) output gives up to +10 absolute accuracy points across three LLMs. — [Source](https://arxiv.org/html/2410.10813v2)
- **A-MEM (Xu et al., 2025; NeurIPS 2025; arXiv:2502.12110)** — Zettelkasten-style notes with LLM-generated keywords, tags and contextual descriptions, LLM-decided links, and "memory evolution" that rewrites old notes when new ones arrive. On LoCoMo with GPT-4o-mini, multi-hop F1: LoCoMo baseline 25.02 → A-Mem 27.02; temporal F1 18.41 → 45.85; single-hop 40.36 → 44.65. **But adversarial/abstention F1 fell from 69.23 → 50.03**, and with GPT-4 single-hop fell 61.56 → 48.43 and adversarial 52.61 → 36.35 — gains are not uniform across question types. — [Source](https://arxiv.org/html/2502.12110v11)
- **A-MEM, DialSim** — F1 3.45 vs LoCoMo 2.55 (+35%) and MemGPT 1.18 (+192%); ~1,200 tokens per memory operation vs ~16,900 for LoCoMo/MemGPT (85–93% reduction). All compared methods used identical system prompts, which isolates the memory structure from prompt wording. — [Source](https://arxiv.org/html/2502.12110v11)
- **A-MEM ablation** — removing link generation and memory evolution drops GPT-4o-mini multi-hop F1 from 27.02 → 9.65; removing only memory evolution gives 21.35. — [Source](https://arxiv.org/html/2502.12110v11)
- **Mem0 (Chhikara et al., 2025, arXiv:2504.19413)** — industry preprint. Reports 26% relative improvement in LLM-as-a-Judge over OpenAI's memory on LOCOMO; graph memory adds ~2% overall; 91% lower p95 latency and >90% token-cost saving vs full-context. Compared against RAG, full-context, open-source memory and dedicated memory platforms. — [Source](https://arxiv.org/abs/2504.19413)
- **Zep (Rasmussen et al., 2025, arXiv:2501.13956)** — industry preprint, temporal knowledge graph ("Graphiti"). Beats MemGPT on its own DMR benchmark 94.8% vs 93.4%; claims up to 18.5% accuracy improvement on LongMemEval and 90% lower latency. — [Source](https://arxiv.org/abs/2501.13956)
- **Agent Workflow Memory (Wang et al., 2024, arXiv:2409.07429)** — induces reusable *workflows* from past trajectories (procedural memory) and injects them into future generations. On web navigation (not coding): +24.6% relative success on Mind2Web, +51.1% on WebArena, and +8.9 to +14.0 absolute points as train/test distribution gap widens; also reduces steps to solve WebArena tasks. — [Source](https://arxiv.org/abs/2409.07429)
- **Reflexion (Shinn et al., 2023, arXiv:2303.11366)** — verbal self-reflection stored in an episodic memory buffer across retries reaches 91% pass@1 on HumanEval vs 80% for the prior SOTA GPT-4. This is within-task trial-and-error on a coding benchmark, not persistent memory across sessions; it is the clearest early coding-specific memory result. — [Source](https://arxiv.org/abs/2303.11366)
- **Lost in the Middle (Liu et al., 2023, TACL; arXiv:2307.03172)** — multi-document QA and KV retrieval degrade significantly when relevant information sits in the middle of a long context, even for explicitly long-context models; performance is highest at the beginning or end. This is the mechanistic reason a "just put everything in the prompt" strategy degrades at scale. — [Source](https://arxiv.org/abs/2307.03172)

### Inferences
- The strongest generic-agent gains are on *narrow* tasks: recalling a specific past fact, multi-hop lookup over synthetic keys, or retrieving indirectly stated user details. Those conditions reward precise storage/retrieval and are exactly where memory systems shine.
- structured organization (graphs, multi-key indexing, time awareness, reflection synthesis) consistently outperforms flat vector storage, but the incremental gains over a good RAG baseline are typically single digits to ~10 points, not order-of-magnitude.
- Chat-assistant memory products are, as of the LongMemEval measurement (August 2024), far worse than simply giving the model the whole history when the history is short enough. Memory's value proposition is scale and cost, not accuracy on short histories.
- Evidence quality is uneven: LongMemEval, A-MEM, MemGPT and Reflexion are peer-reviewed or strong conference papers; Mem0 and Zep are vendor/authored preprints with an obvious interest in the outcome, and their numbers should be read as vendor benchmarks rather than independent replications.

### Gaps
- No source found for a paper titled exactly "MemoryBench"; repeated arXiv search attempts for it failed with HTTP 400. LongMemEval, LoCoMo, DialSim, DMR and MemoryBank are the benchmarks actually named in the primary papers reviewed.
- I did not verify the exact venue of Generative Agents and Reflexion from their arXiv metadata (both are widely cited as UIST 2023 and NeurIPS 2023 respectively); the notes cite arXiv IDs to avoid overclaiming.
- No privacy-focused empirical study of persistent agent memory was found in this pass (see Key Question 3).

## Key Question 2: Is there peer-reviewed or strong preprint evidence that persistent memory improves coding-agent outcomes (SWE-bench style tasks, multi-session debugging)?

### Takeaway
Yes, but almost all of it is very recent (2026), preprint-only, and measures *retrieved repository history or evolved harness state*, not a long-lived personal memory of the user. The cleanest result is Chronos: giving SWE-Agent a structured, graph-linked memory of merged pull requests lifts mean SWE-bench Verified resolution from 69.2% to 72.9% across six backbones (+3.7 points), with smaller but consistent gains on SWE-bench Pro and FEA-Bench Lite. A parallel line of work trains the agent to write and read its own files as memory, and a third shows memory governance matters more than raw storage (gains of 2.4–7.9 points from validating what enters memory). Several papers also find *null* or efficiency-only effects, which is important counter-evidence.

### Cited Findings
- **Chronos (Yin et al., October 2026, arXiv:2610.11578; preprint)** — distills merged PRs into structured "experience cards" linked by a typed graph (code-level, developer-intent, organizational relations); semantic search finds entry cards, weighted multi-hop expansion retrieves connected changes; the same memory guides patch generation (patch agent + validation strategy agent) and patch selection ("evolution steward"). On **SWE-bench Verified**, mean resolution across six LLM backbones with SWE-Agent rises **69.2% → 72.9%**, reaching 79.8% with MiniMax M2.5. Same backbone: **SWE-bench Pro 48.3% → 51.7%**; **FEA-Bench Lite 41.0% → 43.5%**. Both experience-guided single-agent variants also beat the base agent. Human evaluation (100 tasks, 10 cards/task): graph-grounded retrieval yields a mean of **2.87 useful cards vs 1.24** for flat semantic retrieval. — [Source](https://arxiv.org/abs/2610.11578)
- **Coding Agent Memory Gym / CAMG-RL (Luo et al., September 2026, arXiv:2609.34422; preprint)** — long-horizon agentic-RL environments with an episode-persistent workspace and ordinary Bash access so the policy learns to create, revise, search and reuse files as memory across context replacements. A 4B and a 9B model trained this way are reported competitive with much larger Qwen3.5-35B-A3B and Qwen3.5-122B-A10B on SWE-bench Verified and MLE-bench Lite. This is "memory as a learned policy behavior", not an external memory product. — [Source](https://arxiv.org/abs/2609.34422)
- **Coding Agent Memory Post-Training II / CAMG-II (Luo et al., November 2026, arXiv:2611.14009; preprint)** — extends the idea to on-policy distillation with a teacher that has a prior over file operations; CAMP-II obtains **2.97× the gain of the strongest OPD baseline** on CAMG-II and the learned file-memory behavior transfers to **Terminal-Bench 2.1 and SWE-Bench Pro V2** with improved success rates. — [Source](https://arxiv.org/abs/2611.14009)
- **MemGuard (Wang et al., August 2026, arXiv:2608.21867; preprint)** — evaluates memory governance on Terminal-Bench 2.0, SWE-Bench Verified, WebArena and Mind2Web across four backbones, five seeds, 16 backbone-benchmark settings, against four memory baselines plus a verifier-only control at matched runtime budgets. It achieves the best success metric and lowest average steps in **all 16 settings**; gains over ReasoningBank (the strongest prior memory baseline) reach **7.9 success-rate points on WebArena, 5.6 step-success-rate points on Mind2Web, and 2.4–3.5 points on the terminal and software-engineering benchmarks**. — [Source](https://arxiv.org/abs/2608.21867)
- **ContextSniper (Luk et al., 2026, arXiv:2607.01916; preprint)** — "code memory" that indexes code and action memory at three abstraction levels, hybrid-ranks candidates and gates long tool output into compact evidence packets. In matched 50-task comparisons: **−51.5% tokens and −36.4% cost** for OpenClaw on SWE-bench Lite; **−40.0% tokens and −28.1% interaction rounds** for OpenCode on SWE-bench Pro. Submitted-resolution rates differed by **one task out of 50** in each setting, i.e. the benefit here is efficiency, not measured accuracy. — [Source](https://arxiv.org/abs/2607.01916)
- **Harnesses That Improve Themselves (Shah & Kathrotia, November 2026, arXiv:2611.22299; preprint)** — a unifying framework for self-improving agent harnesses whose editable components include context and state (memory); experiments on SWE-bench Lite report that **gated modular evolution outperforms both prompt reflection and full-harness rewrites** across models and repositories at a fraction of the token cost. The paper explicitly warns about prompt bloat, benchmark gaming and evaluator tampering as failure modes of self-modification. — [Source](https://arxiv.org/abs/2611.22299)
- **Evo-Harness (Wei et al., 2026, arXiv:2608.15071; EMNLP 2026 Main per metadata)** — "online harness learning": a frozen agent improves by compiling noisy one-shot executions into reusable skill harnesses; evaluated on five benchmarks including TerminalBench2 and SWE-bench. — [Source](https://arxiv.org/abs/2608.15071)
- **One Recipe, Many Harnesses (Yang et al., August 2026, arXiv:2608.10178; preprint)** — fixes an evolution recipe across **8 programming languages (Multi-SWE-Bench) and 3 base models**. The loop improves held-out solve rates over both a minimal seed and the manually designed mini-SWE-agent scaffold in most cells, **but with two null regions**. Gains appear only where there are recoverable execution defects; where defect mass is near zero, gain is near zero. — [Source](https://arxiv.org/abs/2608.10178)
- **Bilevel Coordinated Reflection (Chen et al., September 2026, arXiv:2609.02750; preprint)** — models reflection as stochastic movement over semantic memory states with convergence proofs; on 500 SWE-bench instances the full Kimi-based system resolves **72.2% vs 70.8%** for a public mini-SWE-agent reference. — [Source](https://arxiv.org/abs/2609.02750)
- **EfficientAgent (Shao et al., September 2026, arXiv:2609.33762; preprint)** — not semantic memory but relevant to cost: right-sizing the KV-cache host tier to the agent pool's "reuse working set" on SWE-bench Verified cuts recomputed prompt tokens by **93%** and end-to-end time by **39%**. A too-small tier evicted state before reuse; a badly configured policy caused a **4.3×** increase. — [Source](https://arxiv.org/abs/2609.33762)

### Inferences
- The coding evidence is real but young: every direct SWE-bench memory result above is a 2026 preprint, and none has the peer-review status of LongMemEval or A-MEM. The report writer should present them as "strong recent preprints", not settled science.
- Where memory helps coding agents, what is stored is usually *repo history, prior patches, or learned file-writing behavior* — structured, verifiable, task-relevant artifacts. This is a different thing from remembering a user's preferences across months.
- Magnitudes on hard coding benchmarks are modest (+2 to +4 points on SWE-bench variants) compared with the +30 to +60 points seen on synthetic recall tasks. The more consistent coding benefit is *efficiency* (fewer tokens, fewer steps) rather than raw resolution-rate gains.
- Memory is not uniformly beneficial: the multi-language study found null regions, and ContextSniper found essentially unchanged resolution. Claims that "persistent memory improves coding agents" need to be scoped to what is remembered and what the baseline already knows.

### Gaps
- No peer-reviewed (conference/journal) study was found that specifically tests persistent long-term memory on SWE-bench or multi-session debugging. The closest peer-reviewed coding result is Reflexion's within-task episodic memory on HumanEval.
- I did not find a benchmark that measures memory across genuinely *multiple debugging sessions* on the same repository (e.g. a bug reported, diagnosed in week 1, and fixed in week 3). CAMG's "episode-persistent workspace" is within an episode, not across sessions.
- Only abstracts were verified for the 2026 preprints; full experimental tables, baseline definitions and significance tests were not checked.

## Key Question 3: What are the documented failure modes and costs of memory (stale memory, retrieval noise, hallucinated recall, context bloat, privacy)?

### Takeaway
The literature is unusually candid about failure: stale and conflicting records, records entering memory from failed trajectories, retrieval that stops too early or pulls mostly irrelevant items, agents fabricating missing facts instead of admitting ignorance, and token/latency bills that can exceed the value of the recall. "More memory" is not monotonic — A-MEM's gains plateau and sometimes reverse as retrieved-item count grows, and the working-set study shows a stale convention file is *worse than no file at all*. I found no rigorous empirical study of privacy risks in agent memory.

### Cited Findings
- **Unreliable admission and memory drift** — MemGuard names two failure modes explicitly: "failed trajectories, accidental successes, and misleading observations enter memory because they appear relevant, then mislead later decisions", and "long-running banks accumulate duplicate, stale, and conflicting records that retrieval alone cannot repair". Their fix is to persist verifier outputs as lifecycle metadata (reward, confidence, label, uncertainty) used during retrieval, conflict resolution, summarization and archival. — [Source](https://arxiv.org/abs/2608.21867)
- **Stale guidance is worse than no guidance** — the working-set study reports: "where standard and code disagree, agents follow the standard even when it prescribes the worse code, so a stale convention file costs more than no file". — [Source](https://arxiv.org/abs/2608.16630)
- **Missing memory causes fabrication, not abstention** — same study: "A missing fact produces wrong work rather than absent work: an agent asked to act acts, fabricating the file or guessing the value, so instruments built on reads look for a hole already filled." How often the agent says it is blocked is a property of the model, ranging from every trial to none. — [Source](https://arxiv.org/abs/2608.16630)
- **Overwriting and failure to record indirect information** — LongMemEval's human study found "ChatGPT tended to overwrite crucial information as the chat continues, while Coze often failed to record indirectly provided user information". — [Source](https://arxiv.org/html/2410.10813v2)
- **Early stopping of retrieval** — MemGPT "will often stop paging through retriever results before exhausting the retriever database", so even though it is theoretically unlimited by retriever ranking quality, it remains practically capped by it. — [Source](https://arxiv.org/html/2310.08560v2)
- **Retrieval noise / diminishing returns with more retrieved items** — A-MEM's sweep over k = 10, 20, 30, 40, 50 found improvement "gradually plateaus and sometimes slightly decreases at higher values", especially for multi-hop and open-domain tasks: richer context introduces noise and challenges the model's capacity to process longer sequences. — [Source](https://arxiv.org/html/2502.12110v11)
- **Most retrieved memory is irrelevant** — Chronos's human evaluation found only 1.24 useful cards out of 10 retrieved per task with flat semantic retrieval, rising to 2.87 with graph-grounded expansion. — [Source](https://arxiv.org/abs/2610.11578)
- **Context bloat / position effects** — "Lost in the Middle" documents U-shaped position sensitivity in long contexts; LongMemEval shows 30–60% QA degradation when evidence sits in a 115k-token history even for long-context models; MemGPT is explicitly motivated by the quadratic cost of self-attention and the inability of long-context models to use added context effectively. — [Source](https://arxiv.org/abs/2307.03172); [Source](https://arxiv.org/html/2410.10813v2); [Source](https://arxiv.org/html/2310.08560v2)
- **Cost of memory operations** — A-MEM reports ~1,200 tokens/operation vs ~16,900 for LoCoMo/MemGPT (85–93% reduction) but still ~5.4 s per operation with GPT-4o-mini; Mem0 reports 91% lower p95 latency and >90% token savings vs full-context; ContextSniper reports 36–52% token/cost reductions; EfficientAgent shows a misconfigured cache policy can increase work 4.3×. — [Source](https://arxiv.org/html/2502.12110v11); [Source](https://arxiv.org/abs/2504.19413); [Source](https://arxiv.org/abs/2607.01916); [Source](https://arxiv.org/abs/2609.33762)
- **Non-monotonic accuracy across question types** — A-MEM improves temporal and multi-hop QA but *reduces* abstention/adversarial and single-hop accuracy for GPT-4 and GPT-4o-mini, so memory can make a model less calibrated on questions it should refuse. — [Source](https://arxiv.org/html/2502.12110v11)
- **Self-modification hazards** — self-improving-harness work flags prompt bloat, benchmark gaming and evaluator tampering as recurring failure modes when agents rewrite their own runtime. — [Source](https://arxiv.org/abs/2611.22299)

### Inferences
- The dominant cost of memory is not storage but *input quality*: bad admissions and stale records poison later decisions, and retrieval quality determines whether memory helps at all. Governance (verification metadata, conflict resolution, archival) is a first-class part of the problem, not an afterthought.
- For coding agents specifically, an available-but-wrong fact is more dangerous than a missing one, because the agent acts on it and produces plausible-looking but wrong code. This argues for memory that is checkable against the repo/tests rather than freely generated prose.
- The "hallucinated recall" reported in the chat literature (overwriting, failing to record, confidently wrong memory) has a coding analogue in the working-set paper's fabrication result. Retrieval-augmented memory does not by itself ground the agent.
- Evidence on privacy is a genuine hole in this literature: none of the papers reviewed measured leakage, unauthorized recall of another user's data, consent, or deletion guarantees.

### Gaps
- No empirical study of privacy, data deletion, cross-user contamination or consent in persistent agent memory was found in this pass.
- No quantified study of "hallucinated memory" in a coding agent (memory that asserts a API/function exists when it does not) was found; the fabrication result in the working-set paper is the closest evidence.
- Long-term drift over truly long horizons (months, thousands of sessions) is asserted by MemGuard but not quantified with a longitudinal dataset in the abstract reviewed.

## Key Question 4: How does memory compare with simply putting durable guidance into the system prompt / instruction files, where research addresses that comparison directly?

### Takeaway
The most direct evidence says *availability of the right fact at write time matters more than where the fact is stored*: supplying a missing fact in the prompt restores success on repository-scale tasks, and distance from the edit does not matter. But two strong caveats cut the other way — a whole-history "just put it in the prompt" baseline beats commercial memory products on short histories, while stale instructions in a durable file are actively harmful. On long histories, prompt-only strategies degrade because of lost-in-the-middle effects and token cost, which is the legitimate niche for memory. Controlled comparisons that hold the system prompt constant find memory structure itself adds value.

### Cited Findings
- **Prompt supply vs missing memory, direct test** — the working-set study supplied and withheld required facts across seven models and five harnesses: "no model completes a task on an unseen API with both channels empty, and putting the facts in the prompt restores success." It also found "availability decides the outcome and distance does not: withholding a fact costs exactly the work it supports, and a supplied fact works as well far from the edit as next to it." Harnesses that all passed every test differed **more than tenfold in tokens consumed** because they rebuilt the same content at different rates; spending more recovered nothing when facts were withheld. — [Source](https://arxiv.org/abs/2608.16630)
- **Stale instruction file** — same study: agents follow the convention file even when it prescribes worse code, so "a stale convention file costs more than no file." — [Source](https://arxiv.org/abs/2608.16630)
- **Whole history in the prompt vs a memory product** — LongMemEval's simpler setting: offline reading with the complete history in context scores 0.9184 (GPT-4o) versus 0.5773 for ChatGPT's memory and 0.3299 for Coze's memory. Authors conclude the result "highlights the gap between building a seemingly personalized chat assistant by recalling isolated facts and demonstrating a genuinely strong memory ability." — [Source](https://arxiv.org/html/2410.10813v2)
- **But prompt-only degrades with length** — the same paper finds 30–60% drops when the whole 115k-token history is given to long-context LLMs; the "Lost in the Middle" paper provides the mechanism. MemGPT's baselines received a lossy recursive summary in the system prompt and were substantially worse than MemGPT's paged full history on DMR. — [Source](https://arxiv.org/html/2410.10813v2); [Source](https://arxiv.org/abs/2307.03172); [Source](https://arxiv.org/html/2310.08560v2)
- **Controlled prompt comparison** — A-MEM explicitly states that "for all baselines and our proposed method, we maintain consistency by employing identical system prompts", so the observed F1 gains are attributable to memory organization rather than better instructions. — [Source](https://arxiv.org/html/2502.12110v11)
- **Memory as an addition to, not replacement for, a coding scaffold** — Chronos applies its PR-history memory on top of SWE-Agent (which already has its own system prompt/scaffold) and adds +3.7 mean points on SWE-bench Verified; its two experience-guided *single-agent* variants also beat the base agent, suggesting the memory alone carries some of the gain. — [Source](https://arxiv.org/abs/2610.11578)
- **Evolved instructions/harness vs hand-written guidance** — "One Recipe, Many Harnesses" compares self-evolved harnesses (which edit prompts, tools and memory) against both a minimal seed and the manually designed mini-SWE-agent scaffold, finding improvements in most language/model cells but two null regions, and gains only where recoverable execution defects exist. "Harnesses That Improve Themselves" finds gated modular evolution beats *prompt reflection* specifically on SWE-bench Lite. — [Source](https://arxiv.org/abs/2608.10178); [Source](https://arxiv.org/abs/2611.22299)
- **Parametric memory substitutes for reading** — the working-set study notes that on SWE-bench, where models likely already know the repositories, reads no longer predict success: built-in parametric memory can substitute for both prompt-provided and retrieved facts. — [Source](https://arxiv.org/abs/2608.16630)

### Inferences
- The research does not support a blanket "memory beats instructions" or "instructions beat memory" claim. The operative variable is whether the specific fact an edit depends on is available and correct at the moment of action. A short, correct system prompt can beat a sophisticated memory system; a stale one is worse than nothing.
- For a codebase, "durable guidance" (convention files, AGENTS.md-style instruction files) is a form of memory with the same failure modes: staleness, conflicting authority, and silent over-reading by the agent. The right design lesson is verification and freshness, not choosing one storage location.
- Recent self-evolution results suggest the best-performing durable guidance is *generated and validated from actual failures* (gated modular evolution, typed failure signals) rather than authored once, and that it helps mainly by closing recoverable execution defects — not by adding general advice.
- Where memory clearly wins over a prompt-only approach is scale: histories beyond the context window, multi-session recall, and token/latency budgets. That is where MemGPT, LongMemEval-style indexing and ContextSniper-style selection show their value.

### Gaps
- No paper was found that directly compares an AGENTS.md/CLAUDE.md-style repository instruction file against an external memory system on the same coding tasks. The closest direct comparisons are the working-set paper's prompt-supply experiments and the harness papers' comparisons against mini-SWE-agent.
- No study quantified how quickly a durable coding convention file becomes stale, or how often agents follow it over contradictory code, beyond the qualitative finding in the working-set paper.
- No independent replication of the vendor memory benchmarks (Mem0, Zep) was found; the LongMemEval comparison to commercial systems is the closest thing to an independent evaluation.
