# Copy truth audit: open items (2026-11-15)

Audit of every user-facing Luna statement (web, lunad, Connect, desktop, Android, quick-start, shared UI).
27 fixers made 585 changes (353 truth or error-cause fixes). Commits: da91f622 to 9d3c04f9.

Reviewed adversarially: web-cloud-protect, web-common-dashboard, web-drives-setup-share, web-gallery, web-pages-b.
Not reviewed (usage limit): the other 22 chunks.

## Product decisions needed

- **web-common-dashboard:** When a drive's summary fails to load, the dashboard card gives an Admin no 'Browse files' button. Members with a grant do get one. The tests assert this on purpose. Should Admins get the button too?
- **web-common-dashboard:** The 'New drive detected' card title stays singular when several drives are waiting. Make it 'New drives detected' for more than one? Several page tests assert the singular heading.
- **web-cloud-protect:** The two delete actions ('Delete now' for old-phrase backups, 'Delete older versions') only mark items, and the real removal waits for the 6-hourly cloud sweep. The toasts now say so. Should lunad start a sweep right after these DELETE calls, so the UI can say 'deleted' again?
- **web-cloud-protect:** The restore success toast reads 'Backup list restored with a warning', but the card never shows the server's `warning` text, only the relink line. Should the toast description show `warning`?
- **web-pages-b:** Shared link page: lunad accepts empty uploads (db.rs:2436), and the drop path on PublicSharePage already uploads empty files. Only the file picker skips them. Remove the picker's empty-file filter, or keep it? The message now says 'This page does not upload empty files.' so it stays true either way.
- **web-pages-b:** The quick-start leaflet (luna/quick-start/src/App.jsx) says an Admin can manage 'every file on Luna', but private items (crates/lunad/src/private.rs) are hidden from an Admin. Should the leaflet copy change to match setup ('An Admin manages people, drives, and settings')?
- **web-settings:** A factory reset keeps the Connect device-token file but unbinds the device from the account. Should a reset forget the device token too, so 'Luna Connect turns off' stays true after setup runs again?
- **web-pages-a:** Album 'lock': in lunad it only stops people from adding or removing photos, but the web UI showed it as 'Private album' and puts a 'do you want to open it' prompt in front of it. Should lock mean privacy (lunad would then have to hide the album) or an edit lock (then the open prompt can go)? The copy now says what the code does: an edit lock.
- **web-pages-a:** Removing a ready drive deletes its drive database. That loses the albums and favorites stored on the drive and the Trash original locations, and private items end up with no record (private.rs says such entries are hidden from everyone). Is that loss intended? Should Remove first restore private items to their real names, or warn more strongly? The modal now states the loss.
- **web-pages-a:** Dashboard greetings: 'Happy Diwali' is fixed on Nov 1 and 'Happy Nowruz' on Mar 21. Diwali's date moves every year, and Nowruz falls on Mar 20 or 21, so most years these show on the wrong day. Should they use computed dates or be removed?
- **web-pages-a:** The login 5xx fallback now says to turn Luna off and on. There is no support channel anywhere in the product, so I removed 'contact support'. Should there be a support link or email?
- **web-files-forms-ops:** FormResponder.jsx renders upload and validation errors as `text-sm text-error` paragraphs. The design rules say status colors are for icons, not text. Should these move to InlineError (or a similar component)? This is a style change, not a copy change, so I did not make it.
- **web-files-forms-ops:** A skip rule whose trigger question changed to a text type still skips on an exact text match, in both the web (isQuestionSkipped) and lunad (question_skipped). Should both ignore rules whose trigger can no longer trigger a skip? The builder copy now says 'may not work' to stay true either way.
- **shared-ui:** The password chip 'symbols' looks like a requirement, but symbols are optional. Should it be relabelled (e.g. 'symbols (optional)') or removed?
- **lunad-api-files:** files/mod.rs drive_root returns FilesError::UnknownDrive while a drive is being erased (drive_is_formatting, ~line 247). Every API then says 'Luna can't find this drive. Make sure it is plugged in, or unplug it and plug it in again.' That is false, and telling someone to unplug a drive during an erase is risky. Should files/mod.rs add a Formatting variant (e.g. 423 'This drive is being erased.') that map_files_err and map_upload_err can name?
- **lunad-api-files:** 'Free up some space' / 'Free up space' is a phrasal verb (not ASD-STE100). It is also the label of the Settings → About → System checks button (StorageBreakdown.jsx), so I kept it as a product term. Keep it, or rename the button and every error together?
- **lunad-files-gallery-office:** A poisoned database lock gives 'Luna's index is busy. Try again.' (files/dav.rs, api/photos.rs) or a false 'can't find this drive' (api/files.rs with_db). Retrying does not help until lunad restarts. Should the shared text be something like 'Luna hit a problem. Restart Luna from Settings, then try again.'? Is there a restart control the text can point to?
- **lunad-files-gallery-office:** Should a drive that is being erased get its own FilesError variant, so file operations say 'Luna is erasing this drive right now' (as files/dav.rs already does) and not 'Luna can't find this drive'?
- **web-lib-a:** Share capability labels in lib/access.js ("Can view", "Can view + upload", "Can view + edit", "Upload only") are a separate vocabulary from the account Read/Write terms in AGENTS.md. Should share permissions also use Read/Write + TermHint, or stay as they are? I left them as they are.
- **web-lib-a:** Phrase check (POST /api/v1/cloud/phrase/check) has no try limit on the server, but the UI has a lockout message for it. Should lunad rate-limit phrase checks like the password proof does?
- **desktop:** Should the Luna Desktop client read lunad's JSON `error` text on every call, not only list_files? The global ureq agent turns 4xx/5xx into bare status codes, so desktop errors are general mappings (413/423/507/5xx) rather than lunad's own words. Doing this means rewriting each call site in luna.rs, and health_api must still treat a 5xx as 'can't ask' rather than 'too old'.
- **desktop:** The update-feed errors in update.rs plain_feed_error (for example 'from a newer kind than this app understands') only reach eprintln (notices.rs:338). Should a failed Windows update check ever be shown to the person?
- **connect-go:** The quick-start and DIY copy promised that the first eight characters of the device token unlock setup from a phone. No code does this: lunad needs the full token off-LAN and no token on-LAN. Build an 8-character unlock, or drop the claim everywhere? This change drops it in Connect API messages; the OnboardingPage.jsx line is listed in outOfChunk.
- **connect-go:** Connect emails and API now say 'cloud backups' (the product term from the wall of shame). Connect web BackupsPage.jsx still says 'cloud copies' in many places, including the delete confirm and the 'Deleting' card. Should the Connect web chunk switch to 'cloud backups' too, for one term per thing?
- **connect-go:** storage.go answers 'This account already has 25 Lunas with cloud backups' (maxLunasPerAccount = 25), but MaxDevicesPerAccount = 1. Luna IDs can outlive device links, so 25 can happen, but the copy may confuse people. Keep it?
- **connect-go:** When the object store (B2) fails, storage.go Put answers HTTP 400, so lunad shows it as a refusal instead of a server outage. Change it to 502 so lunad treats it as temporary?
- **lunad-system-net-core:** The HDMI console (system/console.rs) prints 'Local shell: type root, press Enter at password.' The OS image really sets root with an empty password (luna/os/lib/build-rootfs.d/03.frag and 04.frag). This is a terminal step on a screen people see, and anyone with a keyboard gets a root shell. Should this line stay, move behind the Esc-L-U-N-A gesture, or go?
- **lunad-system-net-core:** Health row 'Linked to Luna Connect.' can show after Luna Connect unlinks this Luna, because only the token presence is checked. Should ConnectStatus expose the persisted 'bound' flag (an API shape change, so lunad-responses.json and the fake lunad would need updates) so the row can say 'This Luna isn't linked to a Luna Connect account'?
- **connect-web-pages:** OnboardingPage: when a signed-in person enters the 'code' step (for example by pressing Back on the Name step), an effect silently DELETEs their bound Luna (/api/v1/devices/{id}), which removes its tunnel and DNS address. Is that intended, or should going back keep the link and only an explicit 'Unbind Luna' remove it?
- **connect-web-pages:** LunaPage: for older devices with no sealed token, Show token can only show a message pointing to the quick-start card. Should DIY tokens minted before sealing get a re-issue path, or is the card message enough?
- **mobile-quickstart:** Videos: on Android 12 and older the app uploads videos too (READ_EXTERNAL_STORAGE covers video, and PhotoBackupWorker queries MediaStore.Video). On Android 13 and later it does not, because the manifest has no READ_MEDIA_VIDEO. Should videos upload on every version (add READ_MEDIA_VIDEO) or on none (drop the video query)? The copy now states the current split.
- **mobile-quickstart:** First upload after setup: SetupActivity.finishSetup calls WorkScheduler.runSoon with no constraints. The first run therefore uploads the whole photo library (since = 0L) on any network, including mobile data, and ignores 'Unmetered Wi-Fi only' (default on). Should the first run respect the Wi-Fi and charging settings? The setup permission text now warns about this.
- **mobile-quickstart:** Quick-start leaflet: the 'Still stuck?' box prints the placeholder 'Support link and QR code will go here.', and 'Still refused? Contact support.' gives no contact. What support URL or contact should be printed? I did not invent one.
- **mobile-quickstart:** The fastlane listing and the app talk only about photos, but on Android 12 and older videos upload too. Should the store text mention videos after the first question is decided?
