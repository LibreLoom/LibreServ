## Steps
1. Move these from the two components into `lib/backupRows.js`, same behaviour for drive rows: `needsALook`, `backupStatus`, `sortByUrgency`, `lastGoodCopyLine`, `creatorName`, `groupByCreator`, `backupHeadline`, `buildBackupRows`, `CARD_PROBLEM_LIMIT`. Remove them (and the `eslint-disable react-refresh/only-export-components` comment if nothing else is exported) from the components.
2. Make them cloud-aware:
   - `buildBackupRows(driveList = [], cloudList = [])`: map each to the `BackupRow` shape in the plan (`destination` = `target_drive_name` for drive, `"Cloud"` for cloud; keep every other field as given, including `private`, `last_checked_at`, `check_problem`, `source_missing`, `old_phrase_copies`). Callers pass `/api/v1/backups` and `/api/v1/cloud/backups` data. Sorted with `sortByUrgency`.
   - `needsALook(row)`: as today for drive; cloud also when `check_problem` or `source_missing` is truthy and `status === "active"`.
   - `backupStatus(row)`: as today; a cloud row whose last run held for a missing source → `{ label: "Waiting for you", variant: "warning" }`.
   - `lastGoodCopyLine(row)`: unchanged wording; works for both kinds.
3. New:
   - `lastTestedLine(rows, now)`: `"9 backups · copies last tested 2 days ago"` using the newest `last_checked_at` of cloud rows; `"9 backups"` when no cloud row was ever checked; `"1 backup"` singular. Use the same relative-time helper `lastGoodCopyLine` uses.
   - `privateGroups(summary, users)`: from `/api/v1/private-backups/summary` → `[{ ownerId, name, deleted, backups, needsLook }]`; `name` = `summary.name` or, for a deleted owner, `"Deleted user"`.
4. Update the two components to import from `../../lib/backupRows.js`. `BackupsCard` still passes only drive data for now: `buildBackupRows(backupsQuery.data)` (T5 adds cloud).
