## Behaviour
1. Data: keep `["backups"]` (`/api/v1/backups`); add `["cloud-backups"]` (`/api/v1/cloud/backups`, the key ProtectSheet already uses, `retry: false`), and `PHRASE_QUERY_KEY` (`getPhraseStatus`). Rows = `buildBackupRows(drive, cloud)`. A failed cloud query just means no cloud rows (Connect may be off); a failed drive query keeps today's "Could not load backups. Try again later."
2. Top: `backupHeadline(rows)` and, below it, `lastTestedLine(rows)` instead of the bare count.
3. Problem list (at most `CARD_PROBLEM_LIMIT` = 3 items in total, most urgent first):
   - Failing rows as today; the destination pill shows `row.destination` (so cloud rows read "Cloud"). For a cloud row the reason is `last_error || check_problem || FALLBACK_REASON`.
   - Phrase reminder when `phrase.data?.check_due` and at least one cloud row exists: an item titled `Check your recovery phrase`, line `It's been a while. Make sure your 12 words still open your cloud backups.`, button `Check now` (`variant="outline" surface="primary"`, the item sits on `surface-primary`) that opens `RecoveryPhraseCheck` with `lunaId={phrase.data.luna_id}`. It counts toward the 3 and comes after failing rows. When the check dialog closes, invalidate `PHRASE_QUERY_KEY` (a successful check clears `check_due`).
   - Private rows are listed like any other: the API only returns them to their owner (and the people on a private drive backup's list).
4. Empty state unchanged: `No backups yet.` / `Click the shield icon beside an item to back it up.` (only when there are no rows at all).
5. `AllBackupsModal` gets `backups={rows}` (both kinds). Opening a problem row still opens `ProtectSheet` with its `source_drive`/`source_path`.
6. Toasts: none here (the card fires no mutations). Don't add haptics; Button/RecoveryPhraseCheck own them.
