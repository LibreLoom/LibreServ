## private_backups.rs routes (all need a signed-in user; use the `Extension<CurrentUser>` pattern of `backups.rs`)
1. `GET /api/v1/private-backups/item?drive=&path=` → `{"private","inside_private","mine","owner_name"}`.
   - `access_list::private_source(conn, drive, path)`: `OwnItem{owner}` → private true; `Inside` → inside_private true.
   - The caller must have Read on the path (`auth::has_cap(.., CAP_VIEW)`), else 404 `"Luna can't find this folder."` (never reveals private items).
   - `mine = owner == user.id`. `owner_name` = owner's display name (else username), "" when not private.
2. `GET /api/v1/private-backups/mine` → `{"items":[{"drive_id","path","name","drive_backups","cloud_backup"}]}`.
   - Mounted drives from `db::list_drives` (state `as_is` or `readonly`, non-empty mount point), `private::under(root, "")`, keep items with `owner == user.id` whose disk folder (`root.join(private::disk_rel(root, &item.path))`) is a directory.
   - `path` is the logical path with a leading `/`, normalized the way `protections.source_path` is stored (`access::normalize_subject_path`) so the web can match it.
   - `drive_backups` = count of active drive rows with `private_owner == user.id` and that source; `cloud_backup` = an active cloud row exists.
3. `GET /api/v1/private-backups/summary` → `{"owners":[{"owner_id","name","deleted","backups","needs_look"}]}`.
   - Admin: one entry per distinct `private_owner` over all protections. Member: only their own entry (or empty list).
   - `deleted` = `owner_state != Active`; `name` = display name or username, `""` for a deleted owner (the web says "deleted user").
   - `needs_look` = rows where `row.state != "active"` or the kind's `state(row, now) != BackupState::Ok` or (cloud) `last_check_problem` is Some. Never return paths, names of items or sizes.
4. `DELETE /api/v1/private-backups/owners/{owner}`: Admin only (403 `"Only an Admin can remove these backups."`); owner must be deleted (409 `"This person still has an account. Only they can remove their private backups."`). Deletes every row of that owner through the same code `backups.rs remove` and `cloud_backups.rs remove` call (drive: `drive_backup::ops::delete`/whatever `remove` uses; cloud: `ops::delete` on a blocking thread with `connect_store`). → `{"removed": n}`. Connect not reachable → 503 with the ops error text.
5. `DELETE /api/v1/private-backups/old-copies`: `ops::retire_old_phrase_now(conn, &user.id, now)` → `{"ok":true}`.
