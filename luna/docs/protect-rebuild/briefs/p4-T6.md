## Changes
1. **`create` (drive_backup.rs ~87):** replace the `inside_private` refusal with:
   ```rust
   let owner = match access_list::private_source(conn, source_drive, &norm) {
       PrivateSource::Shared => String::new(),
       PrivateSource::OwnItem { owner } if owner == user.id => owner,
       PrivateSource::OwnItem { owner } => return Err(refuse(format!("Only {} can back up this item.", owner_name(conn, &owner)))),
       PrivateSource::Inside => return Err(refuse("Back up the private item itself, from its own shield.".into())),
   };
   ```
   `owner_name`: display name, else username, from `db::get_user`; if the account is gone, "its owner". Keep the Read / Write-on-target / whole-drive / same-drive checks in their current order before it.
   - New row: `private_owner: &owner`; access list = `for_private(conn, source_drive, &norm, &owner)` when `owner` is set, else `for_source` as today.
   - `refusal_status` in `api/backups.rs` decides 403 vs 400 by message text; check `grep -n "fn refusal_status" -A8 ../api/backups.rs` and report if "Only … can back up this item." would come out as 400 (T11 owns that file and will adjust; don't edit it).
2. **Manifest (drive_backup.rs ~548):** `private_owner: (!row.private_owner.is_empty()).then(|| row.private_owner.clone())` when a store is first made. Also make sure an existing manifest's `private_owner` is refreshed from the row on each good run (search where `manifest.access` is updated and set `private_owner` next to it).
3. **Stops (ops.rs `stop_reason` ~36):**
   ```rust
   if !row.private_owner.is_empty() {
   ```

   `stop_reason` is used for both drive and cloud rows on every move, so this fixes both.
