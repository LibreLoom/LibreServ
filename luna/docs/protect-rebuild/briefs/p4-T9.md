## Changes in `restore` (~814-940)
Read `sed -n 814,945p api/backup_folder.rs` first. Work out `owner`: `row.private_owner` if the row exists, else `manifest.private_owner.unwrap_or_default()`.

When `owner` is not empty:
1. Only the owner restores: `user.id != owner` → 403 `"Only the owner of this private item can restore it."` (the item's name stays out of the message).
2. Skip the `has_cap(CAP_EDIT)` check (the owner always has Write on their own private item) but keep the "Connect <drive>" check.
3. Item gone: if `crate::private::item_at(mount, &source_sub)` is None:
   - the parent of `source_sub` must exist as a folder, else the existing "The original folder is missing on <label>…" 409;
   - if something already sits at the logical path (`plain_meta(mount.join(disk_rel(mount, source_sub)))` is Some) → 409 `"Something else now has this private item's name. Rename it, then try again."`;
   - else `crate::private::create(mount, &source_sub, &owner)` (read it first: confirm it makes the folder on disk; if not, also `fs::create_dir`). Failure → 500 `"Luna couldn't recreate the private item. Try again."`.
4. Destination: `dest_dir = mount.join(crate::private::disk_rel(mount, &join_rel(&source_sub, &parent_rel)))` instead of the plain join. `restore_name` and the rest stay.

When `owner` is empty, nothing changes. As a side fix, use the same `disk_rel` mapping for shared rows too (a shared source can't be inside a private item, so `disk_rel` returns the same path; this keeps one code path).
