## private_run.rs
```rust
/// Run one private item's cloud backup. Same outcome shape as `run::run_once`.
pub fn run_once(db: &crate::Db, protection_id: &str, store: &dyn CloudStore, accept_missing: bool, now: i64) -> Result<CloudOutcome>;
struct PrivateSealer { owner_public: [u8; 32], luna_id: String, scope: String }
impl Sealer for PrivateSealer { … }
```
Order (mirror `run::run_once` + `run_with_root` + `prepare`; read them first: `sed -n 54,130p run.rs` and `sed -n 177,275p run.rs`):
1. Row; `row.private_owner` must be non-empty (else `Err(anyhow!("This backup is not a private item's backup."))`).
2. Root = `run::source_root(drive_root, &row.source_path)`.
3. `RunSlot::take` or the same "already running" problem.
4. Owner checks, each as `problem_outcome(...)`:
   - `crate::private::owner_state(conn, owner) != Active` → "This private item's owner no longer has an account. An Admin can remove its backups."
   - no `db::get_user_keys(owner)` → "Set up your recovery phrase in Settings → Cloud backup to start this backup."
   - Never check for an Admin phrase. Never call `keys::ensure_key` or `keys::publish_key`.
5. Identity + signer exactly as `prepare` does (same errors).
6. `private::ensure_scope(conn, owner, &owner_public, now)`.
7. Missing source (unless `accept_missing`): newest `db::list_cloud_snapshots(protection_id)` whose `db::private_scope_of_snapshot` is Some; `db::get_private_tree` → `serde_json::from_slice::<Tree>`; `run::most_files_missing(&tree, &root)` → return `CloudOutcome{source_missing: true, ..problem_outcome(SOURCE_MISSING)}`. A read error only logs and goes on (as shared).
8. `db::start_run(conn, run_id, protection_id, &scope.scope, now)`.
9. Meta: `BackupMeta{name, source_drive, source_path, started_by: row.created_by, started_by_name}` (same name rules as `prepare`), sealed with `private::seal_meta`.
10. Outside the lock: `private::publish_scope(store, &signer, &luna_id, &scope, &auth_public)` (auth_public from `user_keys`). Then build `RunContext{ key_version: 0, dedup_key: scope.dedup_key, scope_id/scope from private::scope_of, sealer: Box::new(PrivateSealer{..}), .. }` and call `copy_and_commit`. Always `end_run`, like `run_with_root`.

`PrivateSealer`:
- `wrap_pack_key`: `private::seal_pack_key(..).expect("owner key checked when the phrase was set")`. Before building the sealer, call `crypto::check_public_key(&owner_public)` and return the phrase problem above if it fails, so the expect can't fire.
- `seal_tree`: `private::seal_tree`.
- `finish_record`: `record.sign_with(signer, private::PRIVATE_SNAPSHOT_DOMAIN)` → `(PSNAPSHOTS_KIND, psnapshot_name(scope, id), bytes)`.
- `commit`: `db::commit_private_snapshot_tx(conn, snap, pack_ids, &self.scope, &serde_json::to_vec(tree)?)`.

## private_check.rs
```rust
/// Check a private backup the way plan §5 says: Luna never trusts Connect's answer and never opens the data.
/// Same signature and report type as `check::check`, so `ops::check` can dispatch to it.
pub fn check(db: &crate::Db, protection_id: &str, store: &dyn CloudStore, sample: check::Sample, now: i64) -> Result<check::CheckReport>;
```
Read `check.rs` (`CheckReport`, `Sample`) first. Put the sentence below in `report.problem`; fill the other report fields only where they mean the same thing (e.g. `bad_records`). `Sample::Random(n)` picks up to n data packs; any other variant: every pack.
- Newest private snapshot of the row: `store.get_record(PSNAPSHOTS_KIND, name)` must exist and equal the bytes in `cloud_snapshots.record`, and `verify_with(identity public, PRIVATE_SNAPSHOT_DOMAIN)` must hold. Else "The newest cloud version of this private item is missing or changed. Run the backup again."
- Its tree pack and the sampled data packs from `cloud_snapshot_packs` (use a `db.rs` helper if one lists a snapshot's packs: `grep -n "cloud_snapshot_packs" db.rs`; otherwise a short local `SELECT pack_id FROM cloud_snapshot_packs WHERE snapshot_id = ?1` in this file is fine): `store.get_pack` then `format::sha256(bytes) == id` (pack id is the SHA-256 of the bytes). Else "Part of this private item's cloud backup is missing or damaged. Run the backup again."
- `pscopes/<scope>` must exist; if not, re-publish it with `private::publish_scope` (not a problem).
- Store errors (Connect unreachable) → `Err`, so the caller keeps its "could not check" path.

## Tests (each file's own tests module; `MemoryStore` from `store.rs`)
Set up: temp DB, a mounted test drive with a private item holding two small files (copy the private-item setup used in other tests: `grep -rn "private::create(" --include=*.rs . | grep -i test | head`), Luna identity (see how `run.rs` tests seed it: `grep -n "fn seed\|identity" run.rs | head`), and `user_keys` for the owner from `crypto::derive`.
- `private_run_writes_only_private_records`: after a run, `store.list_records("snapshots")`, `("keys")`, `("recipients")` are empty; `"pscopes"` has 1; `"psnapshots"` has `<scope>.<id>`.
- `owner_secret_opens_the_tree`: get the tree pack, `format::open_pack` with `private::open_pack_key(owner_secret, …)`, then `private::open_tree` → two entries; local `get_private_tree` matches.
- `no_admin_phrase_needed`: no Admin has keys; the run still succeeds.
- `no_phrase_is_a_problem`: owner without keys → the phrase sentence.
- `second_run_reuses_chunks`: second run `reused_chunks > 0`, no new data pack.
- `new_phrase_starts_a_new_scope`: change the owner's `x25519_public` (another `derive`), run → new scope active, old one `old_phrase`, same protection id.
- `source_gone_is_held`: delete both files → `source_missing: true`; with `accept_missing` it runs.
- check: `healthy_private_backup_passes`; `changed_record_is_reported` (overwrite the psnapshot record); `damaged_pack_is_reported` (overwrite a pack with other bytes via MemoryStore internals or `put_pack` under the same id if allowed; if not, delete it).
