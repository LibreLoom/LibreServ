Goal: let T7's private run reuse the copy loop. Shared backups must behave exactly as today; every existing `run.rs` test must pass unchanged (you may only change test code that constructs `RunContext` directly).

## File you may edit

## Steps
1. **Root path.** In `run_once`, replace `drive_root.join(row.source_path.trim_start_matches('/'))` with a new helper and use it there:
   ```rust
   /// The folder on disk for a backup's logical path. A private item's disk name differs from its path.
   pub(crate) fn source_root(drive_root: &Path, source_path: &str) -> PathBuf {
       drive_root.join(crate::private::disk_rel(drive_root, source_path.trim_start_matches('/')))
   }
   ```
   (`crate::private`, the drive-level module, not `backup::cloud::private`.) `disk_rel` maps a path even when the folder is gone, so `source_looks_missing` still works.
2. **Sealer.** Add:
   ```rust
   /// How one kind of backup seals what a run writes. Shared backups use the backup key;
   /// private items seal to their owner (`private_run.rs`).
   pub(crate) trait Sealer: Send + Sync {
       /// The wrapped pack key stored in a pack's header.
       fn wrap_pack_key(&self, pack_key: &[u8; 32]) -> Vec<u8>;
       /// The tree as stored in its tree pack. Its SHA-256 is the record's tree_hash.
       fn seal_tree(&self, tree: &Tree) -> Result<Vec<u8>>;
       /// Sign the record; returns (record kind, record name, bytes) for `put_record`.
       fn finish_record(&self, record: SnapshotRecord, signer: &Signer) -> (&'static str, String, Vec<u8>);
       /// Commit the snapshot locally, in one transaction.
       fn commit(&self, conn: &mut rusqlite::Connection, snap: &db::SnapshotInsert, pack_ids: &[String], tree: &Tree) -> Result<()>;
   }
   pub(crate) struct SharedSealer { pub key_bytes: [u8; 32] }
   ```
   `SharedSealer` does exactly today's code: `crypto::encrypt(&key, PACK_KEY_WRAP_AAD, k)`, `format::encrypt_tree`, `record.sign(signer)` → `("snapshots", snapshot_id, bytes)`, `db::commit_snapshot_tx`.
3. **RunContext** becomes `pub(crate) struct RunContext` with `pub(crate)` fields: `run_id, protection_id, scope, scope_id, dedup_key, key_version, luna_id, signer, meta, sealer: Box<dyn Sealer>`. Remove `key` and `key_bytes` from it: `key_bytes` moves into `SharedSealer`; the `BackupKey` that `publish_key` needs moves into `Publish` (`type Publish = (Recipients, HashMap<String, [u8; 32]>, BackupKey)`). Check `read_tree`/`source_looks_missing` still get the key they need from `db::latest_backup_key` as before (they don't use RunContext; verify with grep).
4. **Use the sealer** in `CopyState::flush` (pack key wrap), and in `copy_and_commit`: tree bytes, tree pack wrap, record kind/name/bytes for `store.put_record(kind, &name, &bytes)`, and the commit. The tree pack builder, chunk insert, pending-pack rows and outcome stay identical.
5. **Missing-source rule as a helper.** Move the last two lines of `source_looks_missing` into
   ```rust
   /// True when most files of the last tree are gone from `root`. An empty tree is never missing.
   pub(crate) fn most_files_missing(tree: &Tree, root: &Path) -> bool
   ```
   and call it from `source_looks_missing`. Make `SOURCE_MISSING` `pub(crate)`.
6. **Visibility:** make `copy_and_commit`, `CopyState` (if needed by the signature), `RunSlot`, `random_id`, `lock`, `problem_outcome`, `hex` (or whatever local hex helper exists) `pub(crate)`. Do not add any private dispatch; T10 does that in `ops.rs`.
